 # 现状分析与下一步开发规划（Folder Insight）
 
 ## 目标与范围
 - 输出当前项目的核心问题与成因
 - 提供可执行的改进方案与阶段化计划
 - 给出可视化方案调研结论与推荐
 - 提出当前阶段可加入的其它功能建议
 
 ## 项目现状概览
 - 架构：Tauri v2 + Rust 后端目录扫描 + React 19 前端可视化
 - 前端视图：树状列表、环形图、矩形树图
 - 后端机制：后台扫描 + 200ms节流的增量事件推送
 - 现有图表：环形图为单层视图；Treemap为扁平数据输入
 
 ## 现有问题与原因分析
 
### 1. 统计界面无法实时更新，且无手动刷新
- 当前图表数据存在 1 秒防抖，主要用于抑制矩形树图的频繁刷新
 - 仅有“选择文件夹”入口，不支持当前路径的重新分析或手动刷新
 
 ### 2. 展开文件列表时排序频繁跳动
 - 目录项大小在增量事件中持续变化
 - 每次更新触发排序，导致展开列表位置不断变化
 - 缺少“稳定排序/冻结排序”的策略
 
 ### 3. 环形统计图效果有限
 - 目前环形图为单层，不支持多层层级分布
 - 需要更适合文件夹层级的多层环形图（Sunburst）
 
 ### 4. 矩形树图无法看见大矩形内部文件分布
 - 目前Treemap仅输入一层数据
 - 缺少多层嵌套结构与下钻展示
 
### 5. 其它阶段性可加入功能未规划
- 无过滤、搜索、忽略规则等效率工具
 - 缺少统计口径切换与进度感知
 - 缺少按文件类型分类统计（系统文件/软件/游戏/视频/音频/图片/文档）
 - 缺少大文件/大文件夹智能检测与排序
 
 ## 解决方案与设计建议
 
 ### A. 实时更新与手动刷新
 - 图表防抖从 1000ms 调整为 200~300ms
 - 或基于“变化阈值”触发刷新（如总量变化超过 5%）
 - 添加“刷新统计”按钮：对当前路径重新分析
 - 增加“暂停/恢复实时更新”开关，降低抖动
 
 ### B. 排序跳动优化
 - 引入“排序冻结”：子项计算未完成时冻结顺序
 - 增加“稳定排序阈值”：小幅变化不触发重排
 - 批量节流排序：每 2s 执行一次
 
 ### C. 多层环形图（Sunburst）调研与推荐
 - 方案1：ECharts Sunburst
   - 优点：组件成熟、交互丰富、实现快
   - 缺点：包体积较大
 - 方案2：D3 Partition + 自绘
   - 优点：高度可定制、体积可控
   - 缺点：开发复杂度高
 - 方案3：Nivo Sunburst
   - 优点：React友好、视觉效果好
   - 缺点：样式适配成本较高
 - 推荐：优先采用 ECharts Sunburst，若体积敏感再考虑D3
 
 ### D. Treemap多层级展示优化
 - 构建多层级数据结构，支持 2~3 层嵌套
 - 展示路径面包屑，支持下钻与返回
 - 大矩形 hover 时显示 Top-N 子项预览
 
 ### E. 统计维度与交互增强
 - 统计口径切换：逻辑大小 / 占用大小
- 搜索过滤：按名称、扩展名、类型分组
 - 忽略规则：目录与扩展名过滤
 - 进度与 ETA：扫描阶段进度提示
 - 分类统计：系统文件/软件/游戏/视频/音频/图片/文档占比
 - 大文件/大文件夹检测：按阈值与占比排序，提供一键定位
 
 ## 分阶段实施计划
 
 ### 第一阶段（稳定性与可用性）
 - 调整图表更新策略（防抖与阈值）
 - 新增“刷新统计”与“暂停/恢复更新”
 - 排序稳定化处理
 - 统计口径切换
 - 分类统计视图与占比展示
 
 ### 第二阶段（可视化深化）
 - Treemap多层级数据与下钻
 - Sunburst多层环形图落地
 - 面包屑导航与分布预览
 
 ### 第三阶段（效率与功能）
 - 搜索与过滤
- 忽略规则
 - 缓存管理与进度估算
 - 大文件/大文件夹智能检测
 
 ## 验收标准（建议）
 - 图表更新延迟 ≤ 300ms
 - 展开列表排序抖动显著减少
 - Sunburst支持 2~3 层展示与下钻
 - Treemap可见多层分布且可下钻
 - 统计口径切换一致且无明显性能回退
