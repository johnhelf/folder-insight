# 项目整体功能盘点与后续开发建议

生成日期：2026-09-20
关联：docs/01 现状分析与开发规划、docs/10 第三轮实现计划

> 本文基于对 `src-tauri/src`（Rust）与 `src/`（React）的只读盘点，梳理当前功能、薄弱点，并给出后续开发方向。仅作建议，实施前需用户确认。

## 一、当前整体功能盘点

**后端（Rust, src-tauri/src）**
- `commands/scan.rs`：目录/磁盘扫描入口，支持 `ALL_DISKS`、`PHYSICAL_DISK:`，持有取消令牌。
- `commands/disks.rs`：跨平台打开资源管理器、物理磁盘/全部磁盘/指定磁盘统计。
- `commands/duplicates.rs`：重复文件查找（分阶段哈希：大小→部分哈希→全量哈希），带取消令牌（rayon 阶段尽力而为）。
- `commands/large.rs`：大文件/大目录报告（Top 50、按大小排序、可取消）。
- `commands/ai.rs`：AI 智能清理建议（构造提示词→调用 AI→解析 JSON），含预览与取消。
- `commands/search.rs`：正则/扩展名/大小过滤的全文搜索，结果数上限 1000，正则长度上限 512。
- `scanner.rs`：扫描参数 `MAX_INITIAL_DEPTH`=3、`MAX_STRUCTURE_PUSH`=20000，防卡顿/OOM。
- `state.rs`：全局状态（大小缓存、磁盘映射、物理磁盘锁、scan/AI/duplicate 三个取消令牌）。
- 重遍历命令均入 `spawn_blocking`，避免阻塞异步运行时。

**前端（React, src）**
- 视图：树 / 旭日图(Sunburst) / 矩形树图(Treemap) / 文件类型 / 重复文件 / AI 洞察。
- `useAppLogic.ts`：核心状态与副作用（扫描、磁盘 30s 自动刷新、增量更新 200ms 批量合并调度、赞助/评分弹窗）。
- `utils/treeUtils.ts`、`scanMerging.ts`：树操作纯函数与扫描增量合并。
- `chartHelpers.ts`：图表数据聚合（深度限制、其他项合并）。
- i18n：11 种语言（含 RTL），自动检测 + 本地持久化。
- 赞助与商店评分弹窗（Windows 专属评分，滑动间隔重提醒）。

**架构合规性**：业务逻辑集中在 hook、树操作纯函数化、UI 用 `t()`、重同步操作 `spawn_blocking`——整体符合项目规则。

## 二、薄弱点与待办（承接前几轮遗留）

1. **CSP（S4）尚未运行验证**：已配置保守 CSP，需打包启动后确认无控制台 CSP 报错；若 HMR/字体/图片被拦需回退放宽。
2. **find_duplicates 取消为"尽力而为"**：rayon 两个哈希阶段无法逐条中断，超大磁盘下取消延迟仍可能明显。
3. **AI API Key 明文存 localStorage**：`ai_api_key` 以明文持久化，本地单机可接受，但建议加掩码/提示风险。
4. **几乎无自动化测试**：尚无 Rust 单测或前端测试，重构回归依赖手工。
5. **重复/搜索/大文件报告都基于一次性全量遍历**：大目录下内存与耗时是主要瓶颈，缓存利用不充分。

## 三、后续开发建议（按优先级分组）

### P1 · 正确性与体验（建议优先）
- **运行验证待测试项**：对 v1.1.7 的 CSP 与 find_duplicates 取消做人工冒烟，写进验收清单。
- **AI Key 存储安全**：至少对 localStorage 中的 api_key 做简单混淆/掩码回显；远期可移入系统凭据管理器权限（需评估跨平台成本）。
- **扫描中断的即时性**：duplicates 的 rayon 阶段改为「分块可中断」（如按块迭代并检查令牌后再发）或降为顺序分段哈希，提升取消响应。
- **空/错误态统一**：搜索、重复文件、大文件、AI 的空态与错误态文案/插画统一，缓解用户对"无反应"的感知。

### P2 · 数据与功能增强
- **缓存复用**：`size_cache` 已存在，但大文件/重复/搜索各自全量扫描；可复用扫描结果缓存，避免重复遍历同目录。
- **文件类型统计增强**：文件类型视图可增加"按扩展名汇总 + 可展开到明细"联动，提升清理依据。
- **导出能力**：重复文件、大文件报告支持导出 CSV/JSON（已做 HTML），便于离线分析。
- **搜索增强**：支持"在结果中打开所在目录"、"搜索历史"、结果分页/提示条数。
- **AI 分析改进**：支持自定义系统提示词、按目录分组的清理方案、风险等级染色（删除/压缩/归档已区分，可加"高风险"标记）。

### P3 · 工程与可维护性
- **自动化测试**：为 `treeUtils`（纯函数）与 Rust 哈希/合并逻辑补单元测试，作为重构安全网。
- **Cargo 特性/依赖瘦身**：审视 rayon/sysinfo/walkdir 使用面，避免无谓依赖（保持资源占用轻，契合移动/轻量定位）。
- **构建产物 CI**：接入 GitHub Actions 自动 `cargo check + tsc + lint`，早发现问题；并可生成多目标产物。
- **移动端考虑**：后端逻辑（扫描/哈希/搜索）与 UI 已解耦，若未来适配移动端，主要工作是便捷交互与触控视图。

### P4 · 合规与发布
- **开源/商店双身份基线**：严格遵循 AGENT.md 红线——公开仓库保持开源 identifier，商店指纹仅本地未提交；发布流程文档化。
- **隐私声明**：AI 功能上传元数据，UI 已有免责声明；建议在设置/关于中补充"数据不上传本地仅元数据"的隐私说明。

## 四、落地节奏建议
1. 先跑 v1.1.7 冒烟（CSP、重复取消），确认无回归。
2. 再做 P1 的 Key 安全与取消即时性。
3. P2 功能按用户最常用路径优先（缓存复用 → 文件类型联动 → 导出）。
4. P3 引入最小测试作为长期护栏，避免大改后回归。

> 本建议仅作方向参考；具体每一项是否实施、优先级与时间，需用户确认后另行规划执行。
